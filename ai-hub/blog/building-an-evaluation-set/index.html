How we test an AI feature before launch

Building a 60-case evaluation set in an afternoon, and how we score it without arguing.

HO✦
JLJordan Lee
Policy & Planning

Every AI feature we ship goes through the same check first: a set of real cases, a scoring guide, and two people scoring independently. It sounds heavy. In practice the first version of an evaluation set takes one afternoon, and it saves us weeks of debating whether a change made things better.

Start with 60 real cases

We aim for about 60 cases drawn from real work in the last three months, with personal details removed. The mix matters more than the number:

  • About 30 typical cases, the kind the tool will see every day
  • About 20 hard cases: ambiguous questions, long inputs, policy edge cases
  • About 10 cases the tool should refuse or escalate

The last group is the one teams forget. A tool that handles every typical case but confidently answers a question it should escalate is not ready.

Write the scoring guide before you look at outputs

For each case we write what a good answer must include and what would make it wrong. Then we score each output on a three-point scale: 2 for correct and usable, 1 for correct but needs editing, 0 for wrong, missing or unsafe. Writing the guide first stops us from adjusting our standards to whatever the model produced.

Two scorers, then talk about the gaps

Two people score every output without seeing each other's scores. On our last run they agreed on 52 of 60 cases. The eight disagreements were the useful part: in five of them, the scoring guide was unclear, and we rewrote it. In three, one scorer had missed an error.

We keep the evaluation set in Prompt Lab next to the prompt it tests, so any change can be rerun in a few minutes.

Deciding when it is good enough

We agree the bar with the team that will use the tool before testing starts. For Meeting Scribe it was: at least 85% of cases scoring 2, and no zeros on action items. The first run scored 71%. After three rounds of prompt changes it reached 88%, and we launched.

We rerun the set every time the model, the prompt or the source content changes. A drop of more than five points stops the release until we understand why.
